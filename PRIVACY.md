# Privacy Policy

`mal-mcp` is a local [Model Context Protocol](https://modelcontextprotocol.io)
server: it runs as a process on your own machine (via `npx` or a local
clone), speaking stdio to your MCP client (Claude Desktop, Claude Code,
etc.). It has no server component of its own, no telemetry, and no
analytics — this policy covers exactly what it does with data, in full,
because there isn't more to say beyond it.

**Read this before connecting your MyAnimeList account.** Unlike the
credential-less read tools, the personal-list tools can both read and
**modify your real MyAnimeList list** — see "Personal-list tools" below for
the exact list of what they can do.

## Data collection

`mal-mcp` collects no data of its own. It has no database, no accounts of
its own, and sends nothing to its maintainer or to any analytics/telemetry
service (verified by inspecting the source — there is no such code path).

The only inputs it handles are:

- **Credentials you supply**, via environment variables in your MCP
  client's own config (e.g. `claude_desktop_config.json`): `MAL_CLIENT_ID`,
  `MAL_ACCESS_TOKEN`, `MAL_REFRESH_TOKEN` (all optional — every read tool
  works with none of them set). These stay in your client's local config
  file; `mal-mcp` never transmits them anywhere except as described below.
- **The OAuth login flow** (`login_mal`/`submit_mal_redirect`): a one-time,
  interactive PKCE authorization against MyAnimeList's own login page,
  described in full under "Personal-list tools" below.
- **Tool call arguments**, generated by the AI model you're using (e.g. an
  anime/manga title, a username, a MAL id, or — for the personal-list
  tools — a status/score/episode update) as it calls one of this server's
  tools on your behalf.

## Usage and third-party sharing

Each tool call results in an outbound HTTPS request to exactly one of two
third-party APIs, carrying only what that specific call needs:

- **Tenrai** (`api.tenrai.org`) — the default backend for every read tool
  (search, details, rankings, seasons, characters, recommendations, and
  reviews). Tenrai is a free, unofficial public API that mirrors MyAnimeList
  data; these calls are **anonymous** — no credential of yours is sent,
  because none is needed. Tenrai publishes an actual
  [privacy policy](https://tenrai.org/privacy) (verified live 2026-07-30,
  policy dated 2026-07-04): it operates from Sweden and is GDPR-governed; it
  logs your IP address and request metadata (endpoint URL, status code,
  timing) — but explicitly not request/response bodies — for
  rate-limiting/abuse-prevention/security, retained up to 90 days then
  purged, and states it does not sell data or use behavioral-tracking/
  advertising cookies.
- **The official MyAnimeList API** (`api.myanimelist.net`,
  `myanimelist.net/v1/oauth2/*`) — reached in two distinct ways:
  - **Resilience fallback for eleven read tools** (`search_anime`,
    `search_manga`, `get_top_anime`, `get_top_manga`, `get_seasonal_anime`,
    `get_upcoming_season`, `get_anime_recommendations`,
    `get_manga_recommendations`, `get_anime`, `get_manga`,
    `get_anime_statistics`): only when you've set `MAL_CLIENT_ID` and Tenrai's
    own call failed, these retry via the official API with your Client ID
    sent as an `X-MAL-CLIENT-ID` header — no OAuth, no user token, just the
    Client ID identifying your registered app to MyAnimeList.
  - **Personal-list tools** (see below): OAuth-authenticated calls carrying
    your access token as an `Authorization: Bearer` header, or (for
    login/refresh) your Client ID and an authorization code/refresh token in
    the request body — never a client secret, since `mal-mcp` registers as
    a public PKCE client with none to send.

  Governed by
  [MyAnimeList's own Privacy Policy](https://myanimelist.net/about/privacy_policy)
  once your request reaches them.

`mal-mcp` sends data to no other destination — no analytics vendor, no
logging service, no server operated by its maintainer.

### Personal-list tools: what they can read and change

These tools require you to connect your own MyAnimeList account — either by
running `login_mal` (a one-time interactive OAuth login) or by pre-supplying
`MAL_REFRESH_TOKEN`/`MAL_ACCESS_TOKEN` yourself. Without a token configured,
these tools refuse to run and return an actionable error instead. Once
connected, the calling AI model can, on your behalf:

- **Read your non-public account data**: `get_my_user_info` (your MAL
  profile and anime watch-status statistics), `get_my_anime_list` and
  `get_my_manga_list` (your full anime/manga list, including status, score,
  progress, dates, tags and comments on every entry).
- **Modify your real MyAnimeList list**: `update_my_anime_status` and
  `update_my_manga_status` add a new entry or change an existing one
  (status, score, episodes/chapters/volumes progress, dates, tags,
  comments) — whatever fields the model passes. `delete_my_anime_list_item`
  and `delete_my_manga_list_item` **permanently remove** an entry from your
  list; MAL's delete endpoint is idempotent and reports success even if the
  entry never existed, so a successful delete result is not proof anything
  was actually removed.

None of this happens unless you've connected an account **and** the model
you're using actually calls one of these tools — but once connected, these
are real, live writes to your MyAnimeList account, immediately reflected on
myanimelist.net, not a local simulation. Review what your MCP client/agent
is about to do before approving a personal-list tool call, the same as you
would for any other tool that acts on a real external account.

## Storage and retention

- **OAuth tokens**: when you run `login_mal` (or supply
  `MAL_REFRESH_TOKEN`/`MAL_ACCESS_TOKEN` and the server obtains a refreshed
  pair), the resulting access + refresh token **are written to disk** at
  `~/.config/mal-mcp/tokens.json` (`%APPDATA%\mal-mcp\tokens.json` on
  Windows; overridable via `MAL_TOKEN_STORE`), with `0600` permissions, so
  the silent-refresh flow survives a server restart. This is the one place
  `mal-mcp` persists anything beyond the running process — everything else
  below is memory-only. Deleting that file (or never running `login_mal`
  and never supplying `MAL_REFRESH_TOKEN`/`MAL_ACCESS_TOKEN`) leaves nothing
  behind.
- **Caching**: successful API responses (search results, details, rankings,
  etc.) are cached in the server process's own memory only (never written
  to disk), for a short configurable TTL (`CACHE_TTL_MS`, default 5
  minutes) to cut latency and avoid hammering Tenrai/MyAnimeList. The cache
  is cleared entirely when the process exits and is never shared across
  machines or users. Paginated/frequently-changing data (reviews, episode
  lists, random picks, your own list) is deliberately **not** cached.
- **Logging**: operational logs go to stderr only (never a file, never a
  remote endpoint), with credentials redacted before anything is written.
  Log verbosity is controlled by `LOG_LEVEL` (default `info`); logs live
  only as long as your MCP client keeps that stderr stream around.
- Beyond the token store, the cache TTL, and the running process's
  lifetime, `mal-mcp` retains nothing. There is no other persistent storage
  layer, and no data is ever sent to the maintainer.
